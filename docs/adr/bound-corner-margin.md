# 端点を揃えられる範囲の角の余白に上限を付け、接続するサイドは端点が揃う位置で評価して選ぶ

## 状況

向かい合うサイドの端点を揃える処理と、段差をなくすために端点をずらす処理は、端点をボックスのサイドの中央の半分にしか置かなかった。角からの余白はサイドの長さの 1/4（最小 8px）で、サイドが長いほど大きくなる。接続するサイドを選ぶ処理は、各サイドを中点だけで評価していた。

ターミナルをサイドバーに並べるプラグインの DFD（`tests/fixtures/terminal-sidebar-dfd.svg`）では、外部エンティティ hc の高さが 1490px で、右のサイドの上下 372.5px ずつに端点を置けなかった。hc の横に並ぶ 6 つのプロセスとの辺は、段差を作るか hc の上や下へ回り込み、屈折が合計 12 回あった（このマシンのフォントで描いた main の出力）。そのうち 1 本は、プロセスが範囲の中にあったのに、サイドの選択が hc の右のサイドを中点（y 785）だけで評価したため、プロセスの上のサイドから L 字で入っていた。

## 決定

- ボックスのサイドの角からの余白を min(max(L/4, 8), max(25, L/8), 50) にする。サイドの中央は越えない。
  - 100px までのサイドは従来と同じ（長さの 1/4、最小 8px）。
  - 100〜200px のサイドは 25px、200〜400px のサイドは長さの 1/8、それより長いサイドは 50px。
  - どの長さでも従来の余白を超えないので、従来揃えられた位置は必ず揃えられる。
  - 円のノードは従来どおり。
- 端点を揃える処理とサイドを選ぶ処理は、同じ関数で「端点を揃えられる範囲」を求める。
- サイドを選ぶときは、2 つのノードの範囲が重なるなら重なりの中央で、重ならないならサイドの中点で評価する。重なるときは両端を同じ位置で評価するので、揃えられる辺はまっすぐと評価される。

## 結果

テストのフィクスチャ 6 つと hc の DFD を、このマシンのフォントで 1 つずつ描いて比べた（main → 変更後）。

| 図 | main | 変更後 |
|---|---|---|
| hc の DFD | 屈折 36、hc の 6 本の屈折 12 | 屈折 21、hc の 6 本の屈折 0 |
| Apache Druid の一部 | issue 56、屈折 129 | issue 48、屈折 119 |
| ストアフロントのアーキテクチャ図 | 屈折 19 | 屈折 19（経路が変わった辺 3 本） |
| 7 つの合計 | issue 56、屈折 320 | issue 48、屈折 294 |

得たもの:

- 長いサイドでも、角から 50px より内側なら、向かい合うノードの高さで端点を揃えられる。
- 揃えられる辺を、サイドの選択がまっすぐと評価する。

失ったもの:

- 100〜400px のサイドでは、端点が従来より角に近づく（160px のサイドで 40 → 25px）。
- テスト（同梱のフォント）の C4 コンテナ図では、屈折が 22 → 23、もつれた交差が 0 → 1 に増えた（API gateway → Dispatch service、Order service → Payment service）。このマシンのフォントでは、ほぼ変わらなかった。
- 16px より短いサイドでは、端点を揃える処理がサイドの中央にだけ端点を置けるようになった（従来はどこにも置けなかった）。この違いが出る図は確かめていない。
- 親を持つ 49 個のスケッチでは計測していない。

## 採らなかった案

- 従来の余白に固定の上限を付ける（min(max(L/4, 8), 24)）: 上限の値に根拠がない。
- ノードのもう一方の大きさ、文字の大きさ、図のノードの典型的な大きさから上限を決める: どれも、端点が角に近く見えるかどうかとは関係がない。
- 人の判断（50px のサイドで 14〜18px、100px で 12〜15px、200px で 24px、400px と 600px で 50px）に合わせた min(max(L/8, 15), 50): 60px より短いサイドで従来より厳しくなる。ストアフロントでは、高さ 48px の API gateway と Order service をつなぐ辺に段差ができ、その短い終端セグメントを伸ばすレイアウトの移動が続いて、Cart service への辺の屈折も増えた（7 つの合計の屈折は 297、ストアフロントは 19 → 23）。
- 同じ形で 1/5 にする（min(max(L/5, 15), 50)）: hc の DFD の屈折が、1/8 のときより多かった（29 と 25）。
- 各サイドを、相手のノードの中心に最も近い位置で評価する: 小さいノードの側の評価位置が大きいノードの中心のほうへ寄るので、両端の高さが合わない。揃えられる辺（hc と 9.2、利用者と 4.2）を、まっすぐと評価できなかった。
