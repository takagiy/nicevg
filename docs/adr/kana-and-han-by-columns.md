# 宣言のフォントにないかなと漢字は、フォールバックのフォントではなく桁数で測る

## 状況

issue #64 で、`font-family` が総称名のとき、かなが描画より狭く測られると報告された。13px の「あいうえおかき」は、nicevg では 71px、Chrome では 91px だった。

宣言のフォントにない文字は、`fontique` がマシンのフォールバックで選ぶフォントで測っていた（[テキストの幅は、マシンのフォントでシェーピングして測る](measure-text-with-fonts.md)）。Windows のフォールバック（DirectWrite）は、かなと漢字に Yu Gothic UI を返す。基準のファミリーとロケールを変えても同じで、zh-CN だけが Microsoft YaHei UI を返した。Yu Gothic UI はメニューなどの UI 用のフォントで、かなの文字 176 字（ぁ〜ゖ、ァ〜ヺ）の幅は 1 字あたり約 0.76em である。総称名に限らず、かなを持たない Arial などを宣言しても同じだった。

ブラウザーは別のフォントで描く。このマシン（Windows 11 25H2）では、DevTools の `CSS.getPlatformFontsForNode` で見ると、Chrome 157 と Edge 157 はかなを Noto Sans JP で描いていた。Chromium は Windows で、スクリプトごとの固定のリストのうち、マシンにある最初のフォントを選ぶ（Blink の `font_fallback_win.cc`）。読み手のブラウザーと OS がどのフォントを選ぶかは、nicevg には分からない。

かなと漢字の幅は、フォントによらず決まっている。このマシンでかなを持つ 46 ファミリーのうち、文書用の 31 ファミリー（Noto Sans JP、Yu Gothic、Meiryo、MS Gothic、BIZ UDGothic、Microsoft YaHei、SimSun など）で、13px の「あいうえおかき」はすべて 91px（1 字 1em）だった。狭いのは、UI 用（Yu Gothic UI、Meiryo UI、MS UI Gothic）とプロポーショナル（MS PGothic、BIZ UDPGothic など）の 15 ファミリーである。

ほかのスクリプトでは、幅がフォントによって変わる。そのスクリプトを持つすべてのフォントで同じテキストを測ると、次のようになった。

| テキスト | フォント | 幅 | Chrome |
|---|---|---|---|
| ภาษาไทย（タイ語） | 3 | 47.0〜53.8px | 53.84px |
| ქართული（グルジア語） | 5 | 45.5〜67.0px | 60.58px |
| Հայերեն（アルメニア語） | 16 | 44.9〜57.1px | 測っていない |

## 決定

- 宣言のフォントにないかなと漢字（スクリプト `Hira`、`Kana`、`Hani` と、その間の句読点）は、マシンのフォールバックのフォントで測らない。どのフォントにもない文字と同じく、East Asian Width の桁数で測る（1 桁はフォントサイズの 0.5 倍）。`fontique` の `set_fallbacks` で、これらのスクリプトのフォールバックを空にする。
- 桁数は、曖昧な幅（East Asian Width の A）の文字を 2 桁と数える（`unicode-width` の `width_cjk`）。かなや漢字の並びに入る ①、※ などを、ブラウザーと同じく 1 字分の幅で測るためである。
- ほかのスクリプトは、これまでどおりマシンのフォールバックのフォントで測る。

## 結果

27 種類のテキストを 6 つの `font-family`（指定なし、`serif`、`sans-serif`、`monospace`、`system-ui`、Arial）で測り、このマシンの headless Chrome 157（en-US）が SVG で描く幅と比べた。

| | Chrome との差の絶対値の合計 |
|---|---|
| 変更前 | 833.75px |
| 変更後 | 99.51px |

`sans-serif` の例:

| テキスト | Chrome | 変更前 | 変更後 |
|---|---|---|---|
| あいうえおかき | 91 | 71 | 91 |
| アイウエオカキ | 90.36 | 68 | 91 |
| 、。（）「」・ | 91 | 63 | 91 |
| 「保存」する | 78 | 59 | 78 |
| データ（JSON）を読む。 | 151.67 | 131 | 152 |
| ①手順 | 39 | 39 | 39 |

得たもの:

- 宣言のフォントにないかなと漢字、その間の句読点は、マシンのフォントによらず同じ幅で測られる。マシンに日本語のフォントがあってもなくても、同じ幅になる。
- OS ごとの分岐も、フォント名の表も持たない。
- どのフォントにもない ①、※ などが、1 字分の幅で測られる。[テキストの幅は、マシンのフォントでシェーピングして測る](measure-text-with-fonts.md) の失ったものの 1 つがなくなった。

失ったもの:

- カタカナのカーニングが入らない。「アイウエオカキ」を、Chrome の 90.36px に対して 91px と測る。
- 隣り合う全角の句読点を詰める描画（CSS の `text-spacing-trim`）は測らない。「、。（）「」・」は、Edge 157 と報告の Chrome では 65px、headless の Chrome 157（en-US）では 91px で描かれる。nicevg は 91px と測る（変更前は 63px）。
- 宣言のフォントにないかなと漢字を、UI 用やプロポーショナルのフォントで描く環境では、実際より広く測る。
- ほかのスクリプトは、マシンのフォールバックのフォントとブラウザーのフォントが違えば、幅が合わない。このマシンでは、タイ語を Chrome の 53.84px に対して 47px、グルジア語を 60.58px に対して 67px と測る（変更前と同じ）。のちに、[Windows ではタイ語とグルジア語を Chrome と同じフォントで測るようにした](thai-and-georgian-as-chrome.md)。
- Windows で日本語のラベルを持つ図は、ラベルとスタイルの `text()` が広く測られ、配置が変わる。テストとフィクスチャの図は `NICEVG_SYSTEM_FONTS=0` で測るので、変わらない。

## 採らなかった案

- Chromium のリスト（`kKatakanaOrHiraganaFonts`）のフォントを、かなと漢字のフォールバックの先頭に置く: このマシンの Chrome との差の合計は 97.83px で、最も近い。しかし、Windows の Chromium の選び方でしかなく、ほかのブラウザーや OS には合う保証がない。OS ごとの分岐とフォント名の表が要る。かなと漢字の幅は文書用のフォントならどれも同じなので、フォントを選ぶ意味がない。
- すべてのスクリプトでフォールバックをやめ、桁数で測る: タイ語が 46px、グルジア語が 46px、エチオピア文字が 26px（Chrome は 53.84px、60.58px、35.39px）になり、差の合計は 236.55px だった。
- スクリプトや Unicode の属性ごとに、1 字の幅の定数を持つ: グルジア語のようにフォントで幅が 47% 違うスクリプトでは、1 つの定数ではどのフォントにも合わない。デーヴァナーガリーのように字が結合するスクリプトは、1 字ごとの定数では測れない（「हिन्दी」は桁数で 33px、フォントで 26.5px）。スクリプトごとに値の表が要る。
- 測ったフォントの名前を SVG の `font-family` に書く: そのフォントがあるマシンでは、描画が測定と一致する（Chrome で `sans-serif, 'Yu Gothic UI'` は 70.89px）。ないマシンでは一致しない（`sans-serif, 'Hiragino Sans'` は 91px）。計測に使ったフォントを集める処理と、出力の `font-family` を書き換える処理が要り、利用者の SVG の見た目も変わる。
- かな（`Hira`、`Kana`）だけを桁数で測り、漢字はフォールバックのままにする: 漢字に続く句読点が Yu Gothic UI の幅で狭く測られる。「「保存」する」は 65px になる（Chrome は 78px）。
- 曖昧な幅を 1 桁と数える: 漢字の前の ① が狭く測られる。「①手順」は 33px になる（Chrome と変更前は 39px）。
