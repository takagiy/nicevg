# 辺がラベルの上を通ることを、ラベルに近いこととは別の critical の問題 `edge-overlaps-label` として報告する

## 状況

検査は、辺がラベルの範囲の上を通る場合も、範囲の外の 8px 以内を通る場合も、`edge-near-label`（error）として報告していた。ほかの「重なる」問題（`edge-overlaps-node`、`label-overlaps`、`label-overlaps-node` など）はすべて critical で、辺とラベルの重なりだけが error だった。

修正は、問題のある辺をまとめて引き直したあと、critical の問題が残った辺を 1 本ずつ引き直す（`lost_edges`）。辺がラベルの上を通っても error なので、1 本ずつ引き直す対象にならなかった。

issue #58 では、まとめて引き直すときに、同時に引き直す辺のラベルを経路探索が見ないため（`pushable_labels`）、edge-1 が edge-2 のラベルの場所を横切った。edge-2 のラベルは置ける場所がなく、自分の線の上に残った。2 件とも `edge-near-label` で、レイアウトにも問題を減らす移動がなく、そのまま残った。

## 決定

- 辺のセグメントがラベルの範囲の内部を通るとき、`edge-overlaps-label`（critical）として報告する。自分の辺のラベルも対象にする。
- 範囲の外で 8px 以内を通るときは、これまでどおり `edge-near-label`（error）として報告する。
- `edge-overlaps-label` の辺も、`edge-near-label` と同じく引き直しの対象にする（`rerouted_for`）。critical なので、まとめて引き直したあとに残れば、1 本ずつ引き直す。

## 結果

テストのフィクスチャの 7 つの図と #58 のスケッチ（`tests/fixtures/label-crowded-sketch.svg`）を、このマシンのフォントで 1 つずつ描いて比べた（0.31.5-beta.37 → 変更後）。

| | beta.37 | 変更後 |
|---|---|---|
| 問題 | 58 | 2 |
| 屈折 | 308 | 306 |
| 経路の長さ | 123,368 | 122,529 |
| 交差 | 101 | 95 |
| 10px 未満で並走する組 | 23 | 17 |
| Apache Druid の図の時間 | 121 秒 | 232 秒 |

得たもの:

- #58 のスケッチ: 問題が 2 → 0 件。edge-1 は左を回り、edge-2 のラベルは自分の線の脇に置かれる。
- Apache Druid の図: 問題が 56 → 2 件。`edge-near-label` 29 件、`label-overlaps-node` 11 件、`edge-label-detached` 10 件、`label-overlaps` 5 件、`edge-bend-near-edge` 1 件が、`label-overlaps` 1 件と `edge-label-detached` 1 件になった。交差は 68 → 63、10px 未満で並走する組は 14 → 8。
- C4 コンテナ図: Payment provider と Messaging provider を右へ 20px 動かす移動がなくなり、2 つは Maps API と同じ列に残る（経路が変わった辺 3 本）。この移動がなくなった理由は追跡していない。
- ほかの 5 つの図は変わらない。テストの snapshot（テスト用の文字幅で描く）も、どれも変わらない。

失ったもの:

- Apache Druid の図の時間が 121 → 232 秒（約 1.9 倍）になった。どこで時間が増えたかは測っていない。1 本ずつの引き直しが増えたためと考えている（推論）。
- ラベルの上を通る辺を `edge-near-label` で探していた利用者には、同じ問題が `edge-overlaps-label` で届く。

変えていないこと:

- まとめて引き直すとき、同時に引き直す辺のラベルを経路探索が見ないこと（`pushable_labels`）と、置けなかった自分の辺のラベルを壁にして引き直さないことは、そのまま。#58 では、その結果を 1 本ずつの引き直しが直している。

## 採らなかった案

- `edge-near-label` を critical にする: ラベルから 8px 以内を通るだけで、ラベルは読める辺も、1 本ずつ引き直す対象になる。「近い」と「重なる」を 1 つのコードで表すので、報告を読む利用者にも区別がつかない。試していない。
- まとめて引き直すときに、同時に引き直す辺のラベルも経路探索の障害物に入れる: ラベルは自分の辺と一緒に動くので、引き直す前に、どこを障害物にするかを決める必要がある。この変更だけで #58 が直ったため、今回は変えていない。
- 置けなかった自分の辺のラベルも、押しのけたラベルと同じく壁にして、場所を取った辺を引き直す: 同じ理由で、今回は変えていない。
