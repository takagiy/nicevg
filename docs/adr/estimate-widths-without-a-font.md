# 名前で指定したフォントで描けない部分の幅は、字とスクリプトから見積もる

## 状況

テキストの幅は、マシンのフォントでシェーピングして測っていた（[テキストの幅は、マシンのフォントでシェーピングして測る](measure-text-with-fonts.md)）。総称名（`sans-serif` など）は OS の既定のフォントに解決し、宣言したフォントにない文字は OS のフォールバックのフォントで測っていた。

読み手のブラウザーと OS が選ぶフォントは、測ったマシンのフォントと違うことがある。issue #64 では、Windows のフォールバック（Yu Gothic UI）がブラウザー（Noto Sans JP）よりかなを狭く描き、ラベルがはみ出した。かなと漢字は桁数で測るようにし（[宣言のフォントにないかなと漢字は、フォールバックのフォントではなく桁数で測る](kana-and-han-by-columns.md)）、Windows のタイ語とグルジア語には Chrome のフォントを使った（[Windows では、宣言のフォントにないタイ語とグルジア語を、Chrome と同じフォントで測る](thai-and-georgian-as-chrome.md)）。どちらも特定の環境の選び方に合わせた対応で、ほかの環境で合う保証はない。

総称名と、名前で指定したフォントにない文字を、どのフォントが描くかは読み手の環境で決まり、nicevg には分からない。文字がはみ出すことは問題になるが、広く見積もりすぎることは、過剰でなければ許容できる。

## 決定

- `font-family` の並びのうち、最初の総称名より前にあり、マシンにあるフォントで描ける文字は、そのフォントで測る。
- それ以外は、文字ごとの幅を足して見積もる。総称名だけのテキスト、名前のフォントがどれもマシンにないテキスト、名前のフォントにない文字が当たる。マシンのフォールバックのフォントは使わない。
- 文字ごとの幅（1em はフォントサイズ）は次のとおりとする。
  - ラテン文字、ギリシャ文字、キリル文字と句読点、記号: 字ごとの表（`src/char_widths.tsv`、1554 字）による。Windows、macOS、Linux、Android の既定の 14 フォントのうち、その字を持つフォントの最大の幅を、0.001em に切り上げた値で、標準と太字がある。14 フォントは Arial、Times New Roman、Segoe UI、TeX Gyre Heros（Helvetica と同じ寸法）、TeX Gyre Termes（Times と同じ寸法）、DejaVu Sans、DejaVu Serif、Liberation Sans、Liberation Serif、Noto Sans、Noto Serif、Roboto、Arimo、Tinos である。
  - Unicode が 2 桁とする文字（かな、漢字、ハングル、全角の英数記号）: 1em。東アジアで 2 桁にする記号（①、※ など）のうち、表にないものも 1em とする。
  - 半角のカタカナとハングル: 0.5em。
  - 絵文字（絵文字の異体字セレクターが続く文字を含む）: 1.38em。
  - 結合文字: 0。
  - 等幅の総称名（`monospace`）のテキストのラテン文字、ギリシャ文字、キリル文字と記号: 0.61em。
  - それ以外のスクリプト: スクリプトごとの定数（下の表）。計測していないスクリプトは 1em とする。
- スクリプトごとの定数は、評価したフォントごとに、Wikipedia の単語の 95% が収まる最小の値を求め、その最大を 0.01em に切り上げた値とする。
  - 単語は、ライプツィヒ大学 Wortschatz の Wikipedia コーパス（27 言語、各 1 万文）と、Wikipedia の API で取得した記事の冒頭（11 言語、各 80〜200 記事）から、ICU の単語区切りで切り出した。スクリプトごとに頻度の上位 3000 語を使う。
  - フォントは、そのスクリプトを描く既定のフォントである。Windows については、Chromium のリストのフォントと Windows のフォールバックのフォントを使う。Linux と Android については、Noto と DejaVu を使う。
- 同梱の Liberation Sans は、名前で指定されたときだけ使う。
- かなと漢字を桁数で測る仕組みと、Windows のタイ語とグルジア語に Chrome のフォントを使う仕組みは、これに置き換える。

得たもの:

- 総称名のテキストの幅が、マシンのフォントに依らない。システムのフォントがあってもなくても同じ値になる（`tests/system_fonts.rs`）。
- 評価したフォントでは、どのスクリプトでも単語の 95% 以上が見積もりに収まる。latest（0.31.4）はワイドでない文字を一律に 0.59em としており、ラテン文字の単語が収まる割合はフォントによって 55〜89% だった。
- OS ごとの分岐と、Chrome のフォントの表がなくなった。

失ったもの:

- 典型的な単語を広く見積もる。ラテン文字の中央値の単語は、Arial より 16%、Times New Roman より 26% 広い。スクリプトごとの定数を使うスクリプトでは、中央値の単語で 9〜86% 広い。アラビア文字やミャンマー文字で特に大きい。
- ラベルが広くなり、図の配置が変わる。テストのフィクスチャの図では、残る問題の数は変わらなかったが、品質の指標が変わった。C4 の図は badness が 1421 から 1442 になり、屈折が 24 から 25 に増え、交差が 4 から 3 に減った。ローンの DFD は badness が 2200 から 2319 になり、屈折が 23 から 25 に増えた。ストアフロントの図は badness が 1364 から 1448 になった。
- Apache Druid の図を総称名で描くと、修正後に残る問題が 47 件から 67 件に増え、斜めの辺が 1 本残る。この図のテストは、図を取り込んだときの Liberation Sans で測るように固定した。
- 1554 字の表を持つ。既定のフォントが変われば測り直しが要る。
- macOS のフォント（Helvetica、Hiragino など）は、同じ寸法の代わり（TeX Gyre）でしか測れていないか、測れていない。
- 名前で指定したフォントは、測ったマシンにあっても、読み手のマシンにないことがある（これまでと同じ）。

## 採らなかった案

- ラテン文字も、スクリプトごとの定数 1 つにする（0.76em）: 字ごとの幅の違い（i は 0.22em、m は 0.83em）を覆うため、Arial の中央値の単語より 49% 広くなる。テスト 35 件が変わり、C4 の図に新しい重なりが出た。
- 全フォントの単語をまとめた p95 を定数にする（ラテン文字 0.70em）: Arial で 37% 広く、DejaVu Serif で収まる単語は 89% になる。
- latest と同じく 0.59em にする: ラテン文字の単語が収まる割合は、フォントによって 55〜89% である。
- これまでどおり、マシンのフォントで測る: 読み手の環境のフォントと合う保証がない。
- 測ったフォントの名前を SVG に書く、文字を図形に変換する: 前者はそのフォントがある環境でしか合わず、後者は文字として選択や読み上げができなくなる。
