# 端点が別のサイドへ移った後に、均等な位置にあった端点だけを並べ直す

## 状況

経路を引いた後の端点の調整は、ノードの手前で短い終端セグメントへ曲がる経路の端点を、曲がる前に向かっていたサイドへ移す。移す端点は、向かっていた線の上か、端点に使える範囲でその線に最も近い位置に置いていた。同じサイドのほかの端点は動かさない。

この結果、端点の位置が乱れていた。

- 向かっていた線が使える範囲の外にあると、端点は範囲の端（サイドの 1/4 か 3/4）に置かれる。そのサイドに端点が 1 本だけでも、中央に来ない。
- 端点が出ていったサイドでは、残った端点が、出ていった端点と分け合っていた位置のままになる。

親を持つ 49 個のスケッチで、端点が 1 本だけのサイド 1442 個のうち、119 個が 1/4 か 3/4 にあった。

サイドの上の端点の位置は、互いに依存している。均等な位置は、そのサイドの端点の数と、意図して置いた端点（段差をなくすためにずらした端点、直線にするためにそろえた端点）の位置で決まる。調整は、端点 1 つの座標だけを書き換え、ほかの端点の位置を導き直していなかった。

## 決定

サイドを移す処理は変えない。移動が採用された後に、移った先のサイドと元のサイドの端点を並べ直す。

- 並べ直すのは、均等な位置にある端点と、向かっていた線が使える範囲の外にあった、移ってきた端点である。
- 段差をなくすためにずらした端点、直線にするためにそろえた端点、ポートで固定した端点、引き直さない辺の端点は動かさない。動かす端点は、これらが残した均等な位置に、サイドに沿った順で置く。端点を最初に均等に分散するときと同じ規則である。
- 端点が均等に置かれたものかどうかは、位置から判定する。そのサイドの端点の数に対する均等な位置にあれば、均等に置かれた端点として扱う。状態は新しく持たない。
- 並べ直しは、交差も屈折も増えず、意図が伝わらない段階の問題も出ないときだけ採用する。採用しないときは、端点は移った位置に残る。

## 結果

親を持つ 49 個のスケッチを、1 つずつ計測した（TypeScript の `text` の幅が見積もりだった時点の状態）。

| | 並べ直さない | 移動の後に並べ直す |
|---|---|---|
| 均等な位置から 2px を超えてずれた端点があるサイド | 692 | 567 |
| 端点が 1 本だけで、1/4 か 3/4 にあるサイド | 119 | 66 |
| 屈折の合計 | 2342 | 2329 |
| 20px 未満の終端セグメント | 260 | 253 |
| 問題の数 | 220 | 202 |
| うち意図が伝わらない段階 | 126 | 123 |
| 処理時間の合計 | 871 秒 | 1158 秒 |

得たもの:

- 端点の乱れが減った。ストアフロントのアーキテクチャ図では、PostgreSQL の右のサイドに 1 本だけ入る辺が、1/4 ではなく中央に入るようになった。
- 問題の数、屈折、短い終端セグメントも減った。

失ったもの:

- 処理時間が 33% 増えた。結果が変わらなかった 18 個のスケッチでは +2% で、増加は結果が変わった 31 個に集中している（+34%）。1 回の調整が遅くなったのか、レイアウトの探索が別の経路をたどったのかは、切り分けていない。
- Apache Druid のスケッチに、斜めの辺が 1 本出た（問題の合計は 38 → 22 に減った）。
- 11 個のスケッチで問題が増えた（最大は PostgreSQL の SELECT の 6 → 14）。減ったのは 7 個である（最大は Apache Druid の 38 → 22、Open edX の 15 → 2）。
- 並べ直すと屈折が増えるときは、乱れが残る。ストアフロントの図では、PostgreSQL の上のサイドに 1 本だけ残ったまっすぐな辺が、1/3 の位置のままである。

## 採らなかった案

- 移動と並べ直しを 1 つの変更として、まとめて採否を決める: 端点の乱れは最も減る（ずれたサイド 543、1/4 か 3/4 のサイド 32）。しかし、問題の数が 229、意図が伝わらない段階が 141、屈折が 2390 に増え、処理時間は 41% 増えた。ほかの辺の屈折が増えると移動ごと採用されなくなり、成立していた移動が減ることが原因と考えているが、確かめていない。
- 意図して置いた端点も含めて、サイドの端点をすべて並べ直す: C4 のコンテナ図で、屈折が 22 → 25、20px 未満の終端セグメントが 0 → 1 に増えた。意図して置いた端点を動かさないようにすると、どちらも元の数に戻った。ずらした端点やそろえた端点が均等な位置に戻され、段差が戻ったためと考えている。
- サイドを移す処理を、端点をずらす処理より先に行う: 並べ直しがずらした結果を取り消さなくなる。しかし、2 ノードの図で、屈折が 1 回 → 2 回に増えた。順序を戻すと 1 回に戻った。サイドを移す案の採否が、ずらす前の経路との比較で決まるためと考えている。
- 移す端点を、範囲の端ではなく均等な位置に直接置く: 移った先のサイドしか直らず、端点が出ていったサイドは乱れたままになる。
- レイアウトの最後に、全体の端点を整える: 乱れた状態のまま、レイアウトの判定が進む。実装も計測もしていない。
