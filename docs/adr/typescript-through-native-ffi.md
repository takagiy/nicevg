# TypeScript からは C の関数を FFI で呼び、Bun では bun:ffi、Node では koffi を使う

## 状況

nicevg を TypeScript からライブラリとして呼びたい。速さは Rust の CLI と同じに保ちたいので、WebAssembly ではなくネイティブのコードを呼ぶ。arrange は全コアのスレッドを使うが、WebAssembly ではそれが難しい。入力は SVG の文字列ではなく、ノードとコネクタのオブジェクトや配列で渡せるようにし、Bun と Node の両方で動かしたい。

開発環境の Rust は GNU ツールチェーン（x86_64-pc-windows-gnu）で、MSVC はない。

## 決定

- Rust 側は `bindings/js` の cdylib（`nicevg_ffi`）で、C の関数 `nicevg_render(要求, 長さ, 返答の長さ)`（修正と配置調整をする）と `nicevg_free` の 2 つを出す。要求と返答はどちらも JSON で、1 回の呼び出しで 1 回だけ受け渡す。
- その関数を、Bun では `bun:ffi`、Node では koffi で呼ぶ。ネイティブライブラリは 1 つで、どちらから呼んでも同じ。どちらを使うかは最初の呼び出しのときに決め、そのときに `bun:ffi` か koffi を読み込む（`src/native.ts`）。モジュールの最上位で待たない（トップレベル await を使わない）ので、CommonJS からも `require()` で読める。
- オブジェクトや配列の入力（Sketch）は、Rust の中で SVG の約束どおりの SVG に組み立て、今の検査・修正・配置調整にかける（`src/sketch.rs`）。経路のないコネクタは両端をノードの中心に置き、修正がノードの辺から辺へ引き直す。
- TypeScript の入口は `render()` 1 つにする。修正と配置調整をして、SVG を表す `Svg` クラスを返す。`Svg` は文字列にでき、ファイルに書け、読み直した図（ノードの範囲、コネクタの折れ点、ラベルの箱、残った問題）と、直したことの一覧を持つ。
- ビルドは `tsc` で `src/` を `dist/` の JavaScript と型定義に書き出す。パッケージは Bun には `src/` を、Node には `dist/` を渡す。テストは Bun で `src/` を、Node でビルドした `dist/` を、どちらもパッケージ名で読み込んで確かめる。

## 結果

得たもの:

- 配置調整の速さは CLI と同じで、出力もバイト単位で同じ（4 つの例の図で、Bun と Node の両方で確かめた）。融資審査 DFD は Bun で 1.93 秒、Node で 1.93 秒、CLI で 1.98 秒。
- ネイティブ側は GNU ツールチェーンのままビルドでき、関数 2 つで済む。TypeScript の型は手で書いた `src/index.ts` にまとまる。
- 図の読み書き、修正、配置調整は今の SVG の処理をそのまま使うので、TypeScript から渡した図も CLI と同じ検査・修正を受ける。
- ソースは TypeScript の書き方を制限されない。Node 向けの JavaScript は `tsc` が書き出す。

失ったもの:

- Node では koffi に依存する。koffi はインストール時にスクリプトでネイティブのバイナリを用意するので、Bun では `trustedDependencies` に入れる必要がある。
- 描画は呼んだスレッドを止める。大きな図の配置調整では 1〜2 秒、イベントループが止まる。
- 毎回 JSON と SVG に変換する。今の図では処理全体に比べて無視できるが、変換の分だけ無駄がある。
- Sketch で表せるのは矩形と円のノード、入れ子、コネクタとそのラベルまで。矢じりの形やスタイルは渡せない。
- プラットフォームごとのネイティブライブラリを配る仕組み（npm のプラットフォーム別パッケージなど）はまだない。今は `bun run build` で手元で作る。
- Deno では試していない。

## 採らなかった案

- napi-rs で Node-API のアドオンにする: Node と Bun の両方で動き、非同期の呼び出しや型の生成もできる。ただ、Windows では MSVC 向けにしか試されておらず、手元の GNU ツールチェーンで作れるかが分からなかった。FFI なら同じ DLL をどちらのランタイムからも呼べる。
- Node の型の取り除き（type stripping）で `src/` の .ts をそのまま動かす: Node は `node_modules` の中の .ts を動かさず、`const enum` やコンストラクタの引数プロパティも扱えない。書き方を縛るより、`tsc` でビルドするほうが素直。
- WebAssembly（wasm-bindgen）: どのランタイムでも動くが、arrange のスレッドを使えず、遅くなる。
- Sketch を SVG にせず、図の内部表現を直接組み立てる: 変換の無駄はなくなるが、修正の各段階が SVG の文書を書き換える作りなので、大きく作り直すことになる。
