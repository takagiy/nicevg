# 親は子に合わせて広げ、スタイル付きの親はレイアウトの後に描く

## 状況

利用者から、親ノードの大きさを中に入れたノードに合わせて自動で決めてほしい、という意見があった。例の図（`bindings/js/agent-sketches`）の 169 個のうち 49 個に親があり、ほとんどの親で `width`・`height` を手で書いていた。

これまでの nicevg は、親の大きさを子に合わせて変えなかった。

- 配置の調整（`arrange.rs` の `allows_one`）は、子を持つノードを動かさず、子は親の枠との余白を保てる範囲（`CONTAINER_MARGIN`、12px）でしか動かさない。
- 修正（`fix.rs`）が親を広げるのは、親自身のラベルが収まらないとき（`expand_nodes`）だけだった。子が枠からはみ出していることを報告する検査はなかった。
- スタイルで描いたノードの大きさは変えない（docs/idea/custom-node-style.md、docs/idea/basic-shapes-as-styles.md）。スタイルは 1 回だけ呼んで描き、nicevg はそれを動かすだけだった。

nicevg の方針は、図の意図を保ちながら、直せる問題を直すこと。子が親の枠からはみ出すのは直せる問題で、利用者が書いた親の大きさや位置は意図である。

## 決定

### 親の位置と大きさ

- 親は、子と余白が収まるように広げる。縮めはしない。
- `x`・`y`・`width`・`height` を書いた親は、その位置と大きさを最小の枠とする。子がはみ出すときだけ、はみ出す向きに広げる。書かなかった親は、子を囲む範囲に余白を足した枠にする。子を持たないノードで `x`・`y` を省くとエラーにする。
- 親自身の文字（タイトルなど）に重なる子は、問題 `parent-text-overlap` として報告し、修正でその文字から余白の分だけ離れる、下か右の近いほうへ動かす。上や左へ動かすと、親が左上へ広がり、スタイルが新しい左上から文字を書き直すので、また子に重なるため。親の枠は文字のために広げず、動いた子がはみ出せば、上のとおり子のために広がる。文字をよけるのは子の置き方の役目で、親の大きさの役目ではないため。
- 余白の既定は 12px（`CONTAINER_MARGIN`）。SVG では、`data-node` のグループか、枠を表す要素（`<rect>`、スタイル付きのノードでは `data-bounds` の要素）の `data-padding` で変えられる。両方にあればグループのほうを使う。ネイティブの Sketch では `padding` で指定する。
- 広げるのは、nicevg が枠を書き換えられる親だけ。SVG の `<rect>` の親、ネイティブの Sketch の矩形の親、TypeScript の Sketch の親が対象。`data-custom` の親は、今までどおり動かさず広げない。
- 入力の時点で子が枠からはみ出しているか、余白を切っている親は、問題 `node-outside-parent` として報告し、修正で広げる。広げた親が兄弟のノードに重なるか近づきすぎれば、ほかのノードどうしと同じく、修正がそのノードを離す（`separate_nodes`）。
- 配置の調整は、子の移動で親が広がることを許す。広がった親が隣とぶつかる移動は、ほかの移動と同じく、問題を増やすので採らない。親が入れ子なら、広がりは外側の親へ伝わる。

### TypeScript の Sketch の親を描く手順

TypeScript の Sketch の親は、レイアウトの前に仮の大きさで、レイアウトの後に決まった大きさで、スタイルを 2 回呼んで描く。

1. **仮に描く**: 子を囲む大きさを `width`・`height` に入れてスタイルを呼ぶ。書いた値があれば、そちらを渡す。親が入れ子なら、内側の親から順に描く。外側の親が囲む子の範囲は、内側の親の仮の絵で決まるので、入れ子の深さだけ往復する。
2. **レイアウトする**: 親を、nicevg が書き換えられる矩形として扱う。仮の絵から次のものを読み、レイアウトに使う。
   - 描かれた枠の大きさ。渡した大きさより大きければ、それを最小の枠にする。
   - 描かれた文字。親自身の文字として、それに重なる子を修正が動かし、配置の調整はそこへ子を動かさない。
   - `data-port` のポート。その位置へ線を引く。
   - `data-padding` の余白。
3. **決まった大きさで描く**: レイアウトで決まった大きさを `width`・`height` に入れて、スタイルをもう一度呼ぶ。
4. **比べる**: 描いた絵の枠の大きさが渡した大きさと同じか、文字とポートの位置（親の左上から）が仮の絵と同じかを調べる。違えば、最後の絵を新しい仮の絵として、Sketch からレイアウトを 1 回だけやり直す。レイアウトの結果から続けないのは、最初の絵で決めた子の動き（文字をよけた移動など）を、最後の絵に合わせて決め直すため。それでも違えば、修正を 1 回かけ、違いを問題 `parent-drawn-differently` として報告する。違いがなければ、何もしない。

スタイルが例外を投げたら、どちらの呼び出しでも、どの親のスタイルかを示すエラーにする。

ネイティブの呼び出しは状態を持たない。1 回の呼び出しは「次に描く親とその大きさ」か「描き上がった図」を返し、途中の状態は返した値に入れて、次の呼び出しで受け取る。この手順を進める関数を TypeScript に 1 つ作り、ライブラリの `render` と `nicevg doc` は、スタイルの呼び方とネイティブの呼び方だけを差し替える。`nicevg doc` では、図のスクリプトが終わった後もサンドボックスを残し、ホストがその中の関数を呼んで親を描かせる。利用者から見た境界は、どちらも `render` のまま変わらない。

### 描き方の手本

`nicevg/style/simple` の `box` に `labelPosition`（`"center"` か `"top-left"`）と `padding` を足す。`"top-left"` のラベルは左上から `padding` の距離に置き、`padding` は枠の `data-padding` にも書く。親には `labelPosition: "top-left"` の `box` を使う。

## 結果

得たもの:

- 親の大きさと位置を手で計算しなくてよくなる。書けば、それが最小の枠として残る。
- 子が親の外へ動けるので、配置の調整が子をよりよい位置に動かせる。
- 子が親からはみ出す問題を、入力の形によらず同じように報告し、直せる。
- スタイルは、受け取った `width`・`height` で描くだけでよい。最初の絵から文字とポートを読むので、タイトルをどこに置いても子はそれをよけ、ポートを付ければそこへ線を引く。
- 中央にラベルを書く `box` で描いた今ある親は、書いた枚のまま描かれる。

失ったもの:

- TypeScript の Sketch の親は、スタイルを 2 回呼ぶ。入れ子の親は、深さの数だけ仮の描画とネイティブの呼び出しを往復する。
- 中央寄せのタイトルや右・下の辺のポートなど、大きさで位置が変わるものを描く親は、大きさが変わるとレイアウトを Sketch からやり直すので、その図だけ時間が最大で 2 倍ほどに延びる。文字が親の幅の半分につれて動く中央寄せのタイトルが子より広いときなど、1 回のやり直しでは収まらず、問題として残ることがある。
- 渡した `width`・`height` を使わず、自分のフィールドやラベルから大きさを決めるスタイルの親は、`parent-drawn-differently` として報告され、レイアウトで広がった分だけ子が枠からはみ出す（`node-outside-parent`）。変更前は、配置の調整が子を書いた枠の中に収めていた。例の図では 49 個中 7 個がこれに当たる。そうしたスタイルを固定した枠として扱う案は、採らなかった。
- 文字のない帯やタブのように、子に重ねたくない絵の部分は、nicevg には分からない。避ける場所は、スタイルが文字か余白で示す必要がある。
- SVG の `<rect>` の親を描いた今ある図は、親を広げれば子をよりよい位置に動かせる場面と、子がもともと親からはみ出している場面で、結果が変わる。後者では、広がった親が兄弟のノードを押しのけることがある。例えば、子の cluster が親の VPC からはみ出し、cluster の辺にまたがるように置いた gateway は、広がった VPC に重なるので外へ押し出され、cluster の辺から離れる。
- `nicevg doc` は、レイアウトの間もサンドボックスを開いておく。
- 親の文字に重なる子は動くので、そういう今ある図では子の位置が変わる。修正をかけず検査だけすると、左上のタイトルと子の重なりが問題として出る。

採らなかった案:

- **親の大きさはレイアウトの前に一度だけ決める**: 配置の調整の前提は変わらないが、子が親の外へ動けず、ぴったり囲んだ親では子がほとんど動けない。
- **親はいつも子から決め、書いた大きさは使わないかエラーにする**: 書いた大きさは、大きめの枠にする・隣とそろえるといった意図なので、捨てられない。
- **親の文字が子より上に来るように、親の上の辺を広げる**: 最初はこう作った。中央にラベルを書く `box` の親では、ラベルを子の上へ逃がそうとして枠が大きく上へ伸び、例の図では 259px 伸びたものがあった。文字をよけるのは子の置き方の役目なので、子を動かす形にした。
- **親の大きさを 2 つ目の引数でスタイルに渡す**: 親のときだけ呼ばれ方が変わり、型でも省略可能にするしかない。
- **スタイルは 1 回だけ描き、nicevg が `data-bounds` の矩形だけを伸ばす**: 一方通行の流れのまま作れるが、右や下に付けたポートや帯が伸びない。
- **親の枠は nicevg が描く**: 親の見た目を自由に描けない。
- **ネイティブから TypeScript へコールバックする**: koffi と `bun:ffi` の両方でコールバックを扱い、`nicevg doc` ではプロセスをまたぐことになる。
- **広げるとほかのノードにぶつかる親は、修正で広げずに報告だけする**: 関係のないノードは動かないが、子が親からはみ出したまま残る。兄弟を避けて離すのは、重なりを直す今までどおりの動きなので、そちらを採った。
- **文字のない帯などを避ける印（`data-keep-clear`）**: そうしたスタイルの例がまだない。
- **親用のスタイル `group` を別に用意する**: `box` との違いはラベルの位置だけで、フィールド 1 つで足りる。
