# テストリスト — SVG diagram

Canon TDD の生きたテストリスト。実装中に気づいたケースはここに追記する。
修正のテストは、修正後の SVG とその品質指標を insta のスナップショットでも記録し、形の変化と品質の後退を検出する。
各項目は `tests/` 配下の実テスト（Given/When/Then のコメント付き）と対応する。
`[x]` = テスト実装済み、`[ ]` = 未実装。

## 図の認識

- [x] `data-node` が付いたグループを解析すると、背景矩形とラベルを持つノードとして認識される
- [x] 矩形とテキストを直接含むグループを解析すると、注釈がなくてもノードとして認識される
- [x] `data-node` が付いたグループが円を含むと、円に外接する矩形を範囲とする円形ノードとして認識される
- [x] 円とテキストを直接含むグループを解析すると、注釈がなくても円形ノードとして認識される
- [x] `data-from` と `data-to` が付いた線を解析すると、指定されたノード間のコネクタとして認識される
- [x] `data-a` と `data-b` が付いた線とグループは、`data-from` と `data-to` と同じくコネクタとして認識され、未対応要素にはならない
- [x] `data-from` と `data-to` が付いたグループの線と多角形の矢じりは、矢じりの先端までを経路とする 1 本のコネクタとして認識される
- [x] コネクタの線と同じグループにある多角形の矢じりは、線の端に接していれば矢じりの先端までを経路とする
- [x] 包含ノードを解析すると、親子の重なりは意図された包含として扱われる
- [x] 自由形状を解析すると、変更せずに未対応要素として報告される

## テキストの見積もり

- [x] 日本語などの全角文字は、1 文字あたりフォントサイズ程度の幅で見積もられる
- [x] `style` 属性で指定した `text-anchor` と `font-size` は、属性と同じく見積もりに使われる
- [x] `text-anchor` と `font-size` は祖先のグループから継承される
- [x] `dominant-baseline="central"` のテキストは、y 座標を上下の中心として見積もられる
- [x] `x` か `y` を持つ `tspan` は新しい行として、行ごとの範囲を合わせた範囲で見積もられる
- [x] 同じ `data-label` を持つ複数のテキストは、1 つのラベルとして範囲を合わせて扱われる
- [x] `data-label` を持つグループは、中のテキストを合わせた 1 つのラベルとして扱われる

## 機械的な検査

- [x] すべての要素が安全余白を含めて viewBox 内にあるとき、問題は報告されない
- [x] 要素が viewBox から切れるとき、切れる辺と必要な描画範囲が報告される
- [x] ラベルがノードの内側余白を侵すとき、必要なボックス寸法が報告される
- [x] 包含関係のないノード同士が重なるとき、重なっている組が報告される
- [x] 同じ段のノード間隔が 20px 未満のとき、不足している間隔が報告される
- [x] ラベル同士が重なるとき、重なっている組が報告される
- [x] ノード外のラベルがノードに重なるとき、重なっている組が報告される
- [x] 包含ノードの中のラベルは、子ノードに重ならなければ報告されない
- [x] コネクタが接続先でないノードを横切るとき、横切られたノードが報告される
- [x] コネクタが接続元や接続先を含む包含ノードの枠を通るとき、横切りは報告されない
- [x] コネクタがラベルから 8px 未満を通るとき、接近しているラベルが報告される
- [ ] コネクタが接続元と接続先の縁で終わるとき、端点の問題は報告されない
- [x] コネクタが接続元または接続先の内部で終わるとき、端点の問題が報告される
- [x] コネクタの最後（または最初）の区間が、端のノードの辺に重なって走るとき、辺に沿った端点として報告される
- [x] `data-allow-overlap` で明示した重なりを解析すると、その重なりは報告されない
- [x] ラベルが円形ノードの内側余白を侵すとき、はみ出しが報告される
- [x] コネクタが円形ノードの外接矩形の角だけを通るとき、横切りは報告されない
- [x] コネクタが円形ノードの円の内部を通るとき、横切りが報告される
- [x] コネクタが円周上で終わるとき端点の問題は報告されず、円の内部で終わるときは報告される
- [x] コネクタ同士が同じ線分上で重なるとき、重なっている組が報告される
- [x] コネクタ同士が交差するだけのとき、重なりは報告されない
- [x] `data-label-for` で紐づいたラベルがコネクタから 16px より離れているとき、離れたラベルが報告される
- [x] 紐づいたラベルがコネクタのすぐ脇にあるとき、離れたラベルは報告されない

## 決定論的な修正

- [x] 描画が viewBox から切れる図を修正すると、安全余白を含む viewBox に拡張される
- [x] viewBox を拡張すると、絶対値の width と height も同じ比率で拡張され、単位を保ったまま表示の縮尺が変わらない
- [x] width と height が割合指定または未指定なら、viewBox を拡張しても変更も追加もしない
- [x] ラベルがボックスに収まらない図を修正すると、ラベルを動かさずにボックスが拡張される
- [x] ラベルが円形ノードに収まらない図を修正すると、中心とラベルを動かさずに半径が拡張される
- [x] 円形ノードへのコネクタを引き直すと、直交経路のまま円周で終わる
- [x] 円形ノードの同じ側へ複数のコネクタを引き直すと、端点を分散させてそれぞれ円周で終わる
- [x] 塗りの指定がない線を折れ線のパスへ引き直すと、塗りなしのパスになる
- [x] 同じ段のノードが重なる図を修正すると、元の順序を保って 20px 以上離される
- [ ] 同じ段のノード間隔が不足する図を修正すると、元の順序を保って 20px 以上離される
- [x] コネクタが無関係なノードを横切る図を修正すると、障害物を避ける直交経路へ引き直される
- [x] 1 回の迂回では障害物を避けられない図を修正すると、複数回折れる直交経路へ引き直される
- [x] 包含ノードの中のノード同士や、中から外へのコネクタを引き直すと、包含ノードを障害物とせず直交経路になる
- [x] 包含ノードの中で引き直したコネクタのラベルは、包含ノードの中に置ける
- [x] 双方向のコネクタが重なる図を修正すると、端点を辺上でずらして重ならない経路へ引き直される
- [x] 同じ 2 辺をつなぐ双方向のコネクタが角を回るとき、端点の並びを入れ替えて互いに交差しない入れ子の経路にする
- [x] 両端とも同じ向きの辺から出入りする双方向のコネクタ（コの字の経路）は、端点の並びを入れ替えて互いに交差しない入れ子の経路にする
- [x] 引き直すコネクタは、ほかのコネクタと同じ線分上に重ならない
- [x] 引き直すコネクタは、ほかのコネクタと 10px 未満の間隔で平行に並ばず、場所があれば 20px 以上離れる
- [x] 引き直すコネクタの端点は、引き直さないコネクタの端点も含めて、辺の上で均等に分散する
- [x] 引き直すコネクタは、端を囲む包含ノードの枠を横切ってよいが、枠に沿って走らない
- [x] 接続する辺は、経路が少し長くなっても折れ曲がりの少ない辺を選ぶ
- [x] 格子線の間に収まる短い線分とも、引き直すコネクタは重ならない
- [x] 迂回路の通り道がほかのコネクタで埋まっていても、その隣に並走する経路で引き直される
- [x] 引き直すコネクタは、接続元と接続先の辺から垂直に出入りし、辺に沿って重ならない
- [x] 端の区間が端のノードの辺に重なる図を修正すると、辺に垂直に入射するように引き直される（端点が揃っていても、辺に垂直でなければ直線にしない）
- [x] 引き直すコネクタは、接続先の手前に矢じりより十分長い直線区間（16px 以上）を残し、最後の折れ曲がりを矢じりから離す
- [x] 多角形の矢じりを持つコネクタを引き直すと、矢じりは新しい終点へ移って最後の区間の向きに回り、線は元と同じだけ手前で止まる
- [x] `translate` を持つグループ内のコネクタを引き直すと、経路はそのグループの座標系で書き込まれる
- [x] 多角形の矢じりは、接続する向きが 90 度・180 度変わっても、また線の始点にあっても、新しい端で最後の区間の向きを指す
- [x] 端点の高さがずれたコネクタを引き直すと、斜めの直線ではなく直交経路になる
- [x] 向かい合う辺をつなぐコネクタは、両端の辺に収まるなら端点の位置を揃えて直線にする
- [x] 揃えた端点は、同じ辺のほかの端点から 10px 以上離れる
- [x] 接続する辺を付け替えると折れ曲がりが減るときは、辺を付け替えて引き直す
- [x] `data-label-for` で紐づいたラベルは、引き直したコネクタの脇へ移動する
- [x] 移動したラベルは、ほかのコネクタとラベルから必要な間隔を保つ
- [x] コネクタに紐づいたラベルがノードに重なる図を修正すると、ラベルはコネクタの脇へ移動する
- [x] `style` 属性で `text-anchor` を指定したラベルを移動すると、`style` の値も書き換えられて脇に収まる
- [x] `dominant-baseline="central"` のラベルを移動すると、y 座標は行の中心として書き込まれて脇に収まる
- [x] 複数行のラベル（`tspan` の行、同じ `data-label` の複数のテキスト、`data-label` のグループ）を移動すると、すべての行が一緒に脇へ移動する
- [x] コネクタから離れたラベルを持つ図を修正すると、ラベルはコネクタの脇へ戻る
- [x] 離れたラベルだけが問題の図を修正すると、コネクタは引き直さずにラベルだけを動かす
- [x] 離れたラベルの置き場がコネクタの脇にないときは、コネクタを引き直してラベルの置き場を作る
- [ ] 修正によってノード位置が変わると、接続するコネクタの端点も新しいノードの縁へ追従する
- [x] 1 回の修正で問題が残る図は、問題が減る限り修正を繰り返す
- [x] 折れ曲がりが同程度なら、すでに接続の多い辺を避けて辺を選ぶ
- [ ] 修正済みの図をもう一度修正すると、SVG は変化しない
- [ ] 未対応の自由形状を含む図を修正すると、自由形状は変更されず診断だけが残る

## ライブラリ API

- [x] `analyze` に SVG 文字列を渡すと、問題、要素、描画範囲を含む構造化レポートが返る
- [x] `fix` に SVG 文字列を渡すと、修正後 SVG、適用した変更、再検査レポートが返る
- [x] 不正な XML を API に渡すと、入力エラーとして失敗する

## CLI

- [x] ヘルプを表示すると、コマンド名が `nicevg` と表示される
- [x] 標準入力の SVG を修正すると、修正後 SVG が標準出力へ出力され、問題が残らなければ成功で終了する
- [x] CLI は修正のあとで常にノードの位置を調整（arrange）し、オプションは受け付けない
- [x] 修正しても問題が残ると、修正後 SVG を出力したうえで、残った問題を標準エラーへ表示して終了コード 1 になる
- [x] 不正な SVG を入力すると、理由を標準エラーへ表示して終了コード 2 になる
- [x] ファイルやサブコマンド、以前の `--arrange` オプションを渡すと、標準入力だけを受け付けるため失敗する

## 配置の調整（arrange）

`arrange` は修正のあとで、入力の大まかな位置関係を保ったままノードを少しだけ動かし、折れ曲がり・交差・混み合いを減らす。

- [x] ノードを少し動かせばコネクタの折れ曲がりがなくなるとき、そのノードを揃えて直線にする
- [x] コネクタ同士の交差は、端のノードを少し動かして解消する
- [x] 動かしたノードは、横に並ぶノードとの左右の順序と縦に並ぶノードとの上下の順序を保ち、各軸 60px までしか動かない（遠く離れたノードとの上下左右は問わない）
- [x] 動かしたノードは、ほかのノードとの間隔を 20px 未満に縮めない（もともと近い場合はそれより縮めない）
- [x] 包含ノードの子は、包含ノードのタイトルに重ならず、枠との余白を 12px 未満に縮めない
- [x] 揃いは同じ包含ノード内のノードどうしでだけ作る。揃った並びの内側のノードは、並びの外側や揃っていないノードより動かしにくい（行の上端・中心・下端をまとめて 1 つのずれと数える）
- [x] 揃いの強さはつながりで決まる: 並びに沿ってまっすぐのコネクタでつながったノードどうしの揃いは、座標だけの揃いより崩しにくい
- [x] 折れたコネクタの直線をふさいでいるノードは、直線が通るだけ動かす（座標だけの揃いなら崩してもよい）
- [x] つながっていても、コネクタが並びに沿ってまっすぐ通っていなければ、その揃いは座標だけの揃いと同じく弱い
- [x] コネクタの角がほかのコネクタの上に乗って、1 本の線につながって見える配置にはしない
- [x] 経路に 20px 未満の小さな段差（ジョグ）を作る移動や、まっすぐだったコネクタを折る移動は避ける
- [x] ストアフロントのアーキテクチャ図では、PostgreSQL の右辺に入る端点を（何本であっても）均等に並べ、charges の折れ曲がりを減らし、API gateway から Cart への呼び出しは 2 回以内の折れ曲がりにし、Auth と Cart の間の Catalog を凹ませない
- [x] ほかのノードが動いたあとで、動いていないノードのコネクタも、引き直せば良くなるなら引き直す
- [x] 同じ辺に複数のコネクタが接続するときは、端点どうしと辺の両端との間隔ができるだけ均等なほど良い
- [x] 2 回以上折れるコネクタの両端のノードも、少し動かす候補にする（注文チェックアウトの DFD では pick list の折れ曲がりが減る）
- [x] 円形ノードは中心だけで揃いを作る（半径の違う円の上端や下端が偶然揃っても揃いとはみなさない）
- [x] 端の区間が極端に短いコネクタが接続するノードと、端の区間がノードのすぐそばでほかのコネクタに横切られているノードも、少し動かす候補にする（注文チェックアウトの DFD の Allocate の下と Manage cart の左）
- [x] 移動によって問題を増やさない
- [x] 移動によって、経路の小さな段差（ジョグ）を増やさない
- [x] 移動によって、10px 未満の間隔で平行に並ぶコネクタを増やさない
- [x] 良くなる移動がない図は変更しない
