# テストリスト — SVG diagram

Canon TDD の生きたテストリスト。実装中に気づいたケースはここに追記する。
修正のテストは、修正後の SVG とその品質指標を insta のスナップショットでも記録し、形の変化と品質の後退を検出する。
各項目は `tests/` 配下の実テスト（Given/When/Then のコメント付き）と対応する。
`[x]` = テスト実装済み、`[ ]` = 未実装。

## 図の認識

- [x] `data-node` が付いたグループを解析すると、背景矩形とラベルを持つノードとして認識される
- [x] 矩形とテキストを直接含むグループを解析すると、注釈がなくてもノードとして認識される
- [x] `data-node` が付いたグループが円を含むと、円に外接する矩形を範囲とする円形ノードとして認識される
- [x] 円とテキストを直接含むグループを解析すると、注釈がなくても円形ノードとして認識される
- [x] `data-from` と `data-to` が付いた線を解析すると、指定されたノード間の辺として認識される
- [x] `data-a` と `data-b` が付いた線とグループは、`data-from` と `data-to` と同じく辺として認識され、未対応要素にはならない
- [x] `data-from` と `data-to` が付いたグループの線と多角形の矢尻は、矢尻の先端までを経路とする 1 本の辺として認識される
- [x] 辺の線と同じグループにある多角形の矢尻は、線の端に接していれば矢尻の先端までを経路とする
- [x] 親を解析すると、親子の重なりは意図された包含として扱われる
- [x] 自由形状を解析すると、変更せずに未対応要素として報告される

## テキストの見積もり

- [x] 日本語などの全角文字は、1 文字あたりフォントサイズ程度の幅で見積もられる
- [x] `style` 属性で指定した `text-anchor` と `font-size` は、属性と同じく見積もりに使われる
- [x] `text-anchor` と `font-size` は祖先のグループから継承される
- [x] `dominant-baseline="central"` のテキストは、y 座標を上下の中心として見積もられる
- [x] `x` か `y` を持つ `tspan` は新しい行として、行ごとの範囲を合わせた範囲で見積もられる
- [x] 同じ `data-label` を持つ複数のテキストは、1 つのラベルとして範囲を合わせて扱われる
- [x] `data-label` を持つグループは、中のテキストを合わせた 1 つのラベルとして扱われる

## 機械的な検査

- [x] すべての要素が安全パディングを含めて viewBox 内にあるとき、問題は報告されない
- [x] 要素が viewBox から切れるとき、切れるサイドと必要な描画範囲が報告される
- [x] ラベルがノードの内側パディングを侵すとき、必要なボックス寸法が報告される
- [x] 包含関係のないノード同士が重なるとき、重なっている組が報告される
- [x] 同じ段のノード間隔が 20px 未満のとき、不足している間隔が報告される
- [x] 同じ段のノードを直接つなぐ辺のラベルが間隔に収まらないとき、ラベルの幅に両側 8px を足した間隔が必要な間隔として報告される
- [x] ラベル同士が重なるとき、重なっている組が報告される
- [x] ノード外のラベルがノードに重なるとき、重なっている組が報告される
- [x] 親の中のラベルは、子ノードに重ならなければ報告されない
- [x] 辺が接続先でないノードを横切るとき、横切られたノードが報告される
- [x] 辺が接続元や接続先を含む親のアウトラインを通るとき、横切りは報告されない
- [x] 接続元や接続先が親のアウトラインにまたがって置かれているとき、その親を通る辺の横切りは報告されない
- [x] 辺がラベルから 8px 未満を通るとき、接近しているラベルが報告される
- [ ] 辺が接続元と接続先の縁で終わるとき、端点の問題は報告されない
- [x] 辺が接続元または接続先の内部で終わるとき、端点の問題が報告される
- [x] 辺の端が接続元や接続先の外にあり、縁から 16px より離れているとき、離れた端点が報告される
- [x] 辺の最後（または最初）の区間が、端のノードのサイドに重なって走るとき、サイドに沿った端点として報告される
- [x] 辺に水平でも垂直でもない区間があるとき、斜めの辺として報告される
- [x] 水平と垂直の区間だけの辺は、斜めの辺として報告されない
- [x] 辺の端（`data-from` や `data-to`）が図にないノードを指すとき、存在しないノードを指す辺として報告される
- [x] 同じ id のノードが複数あるとき、重複した id として報告される
- [x] `data-allow-overlap` で明示した重なりを解析すると、その重なりは報告されない
- [x] ラベルが円形ノードの内側パディングを侵すとき、はみ出しが報告される
- [x] 辺が円形ノードの外接矩形の角だけを通るとき、横切りは報告されない
- [x] 辺が円形ノードの円の内部を通るとき、横切りが報告される
- [x] 辺が円周上で終わるとき端点の問題は報告されず、円の内部で終わるときは報告される
- [x] 辺同士が同じ線分上で重なるとき、重なっている組が報告される
- [x] 辺同士が交差するだけのとき、重なりは報告されない
- [x] `data-label-for` で紐づいたラベルが辺から 16px より離れているとき、離れたラベルが報告される
- [x] 紐づいたラベルが辺のすぐ脇にあるとき、離れたラベルは報告されない

- [x] 同じ 2 つのサイドをつなぐ双方向の辺が角を回るとき、端点の並びを入れ替えて互いに交差しない入れ子の経路にする
- [x] 両端とも同じ向きのサイドから出入りする双方向の辺（コの字の経路）は、端点の並びを入れ替えて互いに交差しない入れ子の経路にする
- [x] 引き直す辺は、ほかの辺と同じ線分上に重ならない
- [x] 引き直す辺は、ほかの辺と 10px 未満の間隔で平行に並ばず、場所があれば 20px 以上離れる
- [x] 引き直す辺の端点は、引き直さない辺の端点も含めて、サイドの上で均等に分散する

- [x] グリッド線の間に収まる短い線分とも、引き直す辺は重ならない
- [x] 迂回路の通り道がほかの辺で埋まっていても、その隣に並走する経路で引き直される

- [x] 移動したラベルは、紐づく辺上の交点（ほかの辺と交わる点）・屈折・両端から、できるだけ離れた場所に置く（それらのうち最も近い点との距離を最大にする）

- [x] 離れたラベルだけが問題の図を修正すると、辺は引き直さずにラベルだけを動かす
- [x] 離れたラベルの置き場が辺の脇にないときは、辺を引き直してラベルの置き場を作る

- [x] サイドが 16px 未満のカスタムノードを含む図も、修正と配置の調整が失敗しない
- [x] 数値でない `points`、合計が f64 を超える `translate`、`NaN` の `data-padding` は、属性値と同じく読まれ、修正が失敗しない

## ライブラリ API

- [x] `analyze` に SVG 文字列を渡すと、問題、要素、描画範囲を含む構造化レポートが返る
- [x] `fix` に SVG 文字列を渡すと、修正後 SVG、適用した変更、再検査レポートが返る
- [x] 不正な XML を API に渡すと、入力エラーとして失敗する
- [x] 要素が 256 段より深く入れ子になった SVG を API に渡すと、スタックを溢れさせずに入力エラーとして失敗する

## CLI

`nicevg` コマンドは TypeScript ライブラリの `bin` で、Node ではビルドした `dist/cli.js` を、Bun では `src/cli.ts` を動かして確かめる（`bindings/js/test/node/cli.test.ts`）。

- [x] ヘルプを表示すると、コマンド名が `nicevg` と表示される
- [x] 標準入力の SVG を修正すると、修正後 SVG が標準出力へ出力され、問題が残らなければ成功で終了する
- [x] CLI は修正のあとで常にノードの位置を調整（arrange）し、オプションは受け付けない
- [x] 修正しても問題が残ると、修正後 SVG を出力したうえで、残った問題を標準エラーへ表示して終了コード 1 になる
- [x] 不正な SVG を入力すると、理由を標準エラーへ表示して終了コード 2 になる
- [x] ファイルやサブコマンド、以前の `--layout` オプションを渡すと、標準入力だけを受け付けるため失敗する
- [x] 多くのプロセスで同時にレイアウトしても、どのプロセスも落ちずに終わる（レイアウトは、古い移動候補を捨てるスレッドを待ってから戻るので、ランタイムがライブラリを外す時に動いているスレッドがない）

## 配置の調整（arrange）

`layout` は修正のあとで、入力の大まかな位置関係を保ったままノードを少しだけ動かし、屈折・交差・混み合いを減らす。

- [x] ノードを少し動かせば辺の屈折がなくなるとき、そのノードを揃えて直線にする
- [x] 大きさが 0 のノードがある図でも、ほかのノードは同じように揃えられる
- [x] 辺同士の交差は、端のノードを少し動かして解消する

## 品質指標

スナップショットに記録する品質指標は、どれも悪いほど大きくなる。悪いものの数か、1 件ごとの悪さの合計なので、悪いものが 1 件増えて指標が小さくなることはない（`tests/quality.rs`）。

- [x] 同じ向きに進む 2 本の間の 20px 未満の段差はジョグで、段差が 20px に足りない長さを悪さとして足す
- [x] ジョグが 1 つ増えると、ジョグの数も足りない長さの合計も増える
- [x] 短い区間で折り返す U 字はジョグに数えない
- [x] 2 本の辺が内側で交わる点を交差として数える
- [x] 辺の端から 20px 以内の交差は、端の近くの交差としても数える
- [x] 端で触れるだけの辺は交差に数えない
- [x] 曲がる前の端の区間が 20px 未満なら短い端として、足りない長さを足す
- [x] 曲がらない短い辺の端は短い端に数えない
- [x] 端子がサイドの角に寄りすぎている量を、サイドの端子を均等に並べたときの間隔の半分に足りない長さで測る
- [x] 端どうしを結ぶ最短の直交経路より長く走った分を遠回りとして測る
- [x] 何度曲がっても、曲がった辺は 1 本と数える
- [x] 40px 以内で並走する区間を持つ辺どうしの交差は、絡んだ交差としても数える

各指標を、人が見比べた判断から決めた重み（docs/idea/quality-weights.md）で合計した悪さ `badness` も記録する。

- [x] 小さなジョグは、何もないところを回る迂回より悪い値になる
- [x] 交差があると、同じ形で交差がないときより悪い値になる
- [x] 同じ長さでも、3 つ目以降の屈折があると悪い値になる
- [x] ジョグが 1 つ増えると、合計の悪さも増える

## ポート

辺の端を、ノードの style が宣言した点（ポート）に固定する（[アイデア](../idea/style-ports.md)）。

### 読み取り

- [x] 独自描画ノードの絵の中の `data-port` を付けた点を、名前の付いたポート（点）として読む
- [x] 辺がポートから出る向きは、点が乗っている範囲のサイドの外向きとする
- [x] 範囲のサイドから外れた点から出る向きは、いちばん近いサイドの外向きとする
- [x] 同じ名前の点が複数あれば、1 つのポートの候補の位置として読む
- [x] 辺の `data-from-port`・`data-to-port` を読み、解析結果の辺に `fromPort`・`toPort` として出す

### 検査

- [x] ポートを指定した端が、そのポートのどの点でも終わっていないとき、ポートから外れた端点として報告される
- [x] 端のノードが宣言していないポートを指定したとき、存在しないポートとして報告される
- [x] ポートがノードの範囲の外にあっても、そのポートで終わる端は、ノードから離れた端点として報告されない
- [x] 同じポートに入る複数の辺が、ポートの手前で重なって合流しても、重なりは報告されない
- [x] 同じポートに入る複数の辺が合流する角は、近接（ニアミス）として報告されない

### 修正

- [x] 経路のない辺のポートを指定した端は、そのポートの点から、ポートの向きに出入りするよう引かれる
- [x] ポートから外れた端点の辺は、ポートの点から出入りするよう引き直される
- [x] 同じ名前の点が複数あるポートは、経路が良くなるほうの点を使う
- [x] 同じポートに入る複数の辺は、どれもそのポートまで直交する経路で引かれる
- [x] 同じサイドに、ポートに固定された端点とポートを指定していない端点があるとき、ポートを指定していない端点は、ポートに固定された端点も含めた端点どうしの間隔が均等に近くなるよう並べる
- [x] 存在しないポートを指定した端は、ポートの指定がないものとして引く
- [x] アウトラインから外れた位置に描かれたポートから出る辺は、ポートに最も近いサイドの向きに出て、直交する経路で引かれる
- [x] 同じ 2 つのノードを結ぶ複数の辺は、どれも自分の経路に引き直される

### 配置の調整

- [x] ノードを動かしても、ポートを指定した端はポートの点から出入りする
- [x] ポートの点にある端点は、サイドの中央から外れていても、サイドの上で偏っていても、正しい位置にあるとみなす
- [x] 向かい合うポートの高さ（または左右の位置）が少しずれている 2 つのノードは、ポートどうしが揃うよう動かして辺をまっすぐにする

### Sketch と TypeScript

- [x] Sketch の辺の `fromPort`・`toPort` を、`data-from-port`・`data-to-port` として書き出す
- [x] 端のノードが宣言していないポートを指定した Sketch は、`edges[i].fromPort`（`toPort`）を示すエラーになる
- [x] TypeScript の辺の端 `"node.port"` は、`.` の前をノード、後をポートとする
- [x] TypeScript の辺の端に `.` が 2 つ以上あるときは、最後の `.` の前をノード、後をポートとする（`"a.b.c"` はノード `a.b` のポート `c`）
- [x] TypeScript の辺の端に `.` を含むノードの id（`"a.b"`）を書くと、そのノードにポートなしでつなぐ

### 受け入れ

- [x] SNS アプリの ER 図をレイアウトすると、すべての外部キーが自分の列の行から出て、参照先の列の行に入る
- [x] SNS アプリの ER 図をレイアウトすると、同じ 2 テーブルを結ぶ 2 本の外部キーも含めて、問題が残らない
