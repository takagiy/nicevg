# 経路探索のヒューリスティックを真の値に近づける

## きっかけ

プロファイル（`examples/profile.rs`）で、arrange の時間の半分以上が経路探索の A* の本体（`search_astar`）だった。融資審査 DFD では 1 回の探索で平均約 2 万状態を訪れている。

ヒューリスティックは、到着点の候補までのマンハッタン距離だけだった。実際のコストには、長さのほかに曲がり（40、3 回目以降 120）、交差（300）、並走の加算が含まれる。そのため推定が実コストよりずっと小さく、A* がゴールへ絞り込めずに広く展開する。

## 前提

- 探索の状態は「頂点 × 直前に進んだ軸 × これまでの曲がり回数（0・1・2 以上）」。
- ヒューリスティック h は状態の関数で、位置・軸・曲がり回数のどれを使ってもよい。条件は、その状態から到着点までのどの続け方の実コストも超えないこと（admissible）。
- h は「残りに最低いくらかかるか」の絶対量。実コストは「長さ ＋ 曲がり ＋ 交差 ＋ 並走 …」と部分の和なので、部分ごとの下限を足して組み立てる。同じ部分を二重に数えると過大評価になる。
- 下限が真の値に近いほど、訪れる状態が減る。見つかる経路のコストは変わらない（同じコストの経路が複数あるときに、どれを選ぶかは変わりうる）。

## 項

```text
h(状態) = 到着点の候補ごとの次の値の最小
          ① 到着部分の加算 ＋ ② 長さ ＋ ③ 最小回数の曲がり ＋ max(④, ⑤ ＋ ⑥)
```

| 項 | 何の下限か | 計算 | 使える状態 |
|---|---|---|---|
| ① 到着部分の加算 | 到着点の候補の加算 | 24px の候補は 0、16px は 8、8px は 16 | すべて |
| ② 長さ | 長さ | マンハッタン距離 | すべて |
| ③ 最小回数の曲がり | 避けられない曲がり | 軸と位置関係で回数を決め、今まで曲がった回数から単価（40 か 120）を足し上げる | すべて |
| ④ 直進が塞がれた分 | 最小回数を超える曲がり、または交差 | min(k × 300, 追加 2 回分の曲がり)。ノードや既存コネクタへの重なりで塞がれていれば追加 2 回分 | 最小回数が 0 か 1 の状態だけ |
| ⑤ 縦の仕切り線 | 横に進む辺での交差と、上下の余分な移動 | 今の位置と到着点の間の各縦線について、越える高さの中で最安の「交差（300 か 0）＋ 上下の回り道」。その最大 | すべて |
| ⑥ 横の仕切り線 | 縦に進む辺での交差と、左右の余分な移動 | ⑤ を縦横入れ替えたもの | すべて |
| ⑦ 並走の加算、縁の 1.01 倍 | — | 0（数えない） | — |

③ の最小回数:

| 今の軸と到着点の軸 | 位置関係 | 最小回数 |
|---|---|---|
| 同じ | 同じ直線上 | 0 回 |
| 同じ | 違う直線上 | 2 回 |
| 違う | — | 1 回 |

曲がりは 1 回ごとに縦横が入れ替わるので、回数の偶奇は軸の組み合わせで決まる。

## 足してよいもの、max にするもの

- ①②③⑤⑥ は実コストの別々の部分の下限なので足せる。⑤ は「横に進む辺の交差と上下の移動」、⑥ は「縦に進む辺の交差と左右の移動」で重ならない。
- ④ は ⑤⑥ と同じ交差を数えうるので、足さずに max を取る。例えば直進が既存コネクタを 1 回だけ横切るとき、④ は min(300, 80) = 80、⑤ は min(300, 迂回の長さ) = 300 になりうる。足すと 380 だが、直進して交差するだけなら実際は 300。
- ④ を最小回数が 2 回以上の状態で使ってはいけない。最小回数で着ける経路が多数あり、どうせ払う 2 回の曲がりを障害物の手前で使えば、交差も追加の曲がりも払わずに済むことがある。最小回数分の曲がりは ③ で数え済みなので、二重に数えることになる。
- 最小回数が 0 回・1 回のときは、最小回数で着ける経路が直進（L 字）の 1 本に決まる。そこから外れれば曲がりの偶奇は変わらないので、少なくとも 2 回増える。

## 例

A（左）から B（右）へ、間に C、その右に D→F の縦のコネクタ e があり、D・e・F が x=440 付近で縦の壁になっている。出発点 (90, 142)、到着点の候補 (550, 126)。

| 項 | 値 |
|---|---|
| ① | 0 |
| ② | 476 |
| ③ | 80（縦軸どうし・違う直線上なので 2 回） |
| ④ | 使えない（最小 2 回） |
| ⑤ | 252（D の上を回るのが最安。e を横切ると 300） |
| ⑥ | 0 |
| h | 808 |

真の値は約 813（D の上を回る経路）。マンハッタン距離だけの推定 476 よりずっと近い。

## 実装の順序

1. ①②③: 状態ごとに O(1)、事前計算なし。
2. ⑤⑥: グリッドを作るたびに、列（行）の隙間ごとの 1 次元距離変換（左右 2 回の走査）と、到着点から外へ向かう最大値の累積を事前計算する（セル数程度）。状態ごとの参照は O(1)。
3. ④: 行・列ごとの「通れない辺」「交差する辺」の累積和で、直進・L 字の判定を O(1) にする。

各段階で、出力が変わらないこと（スナップショット）と、訪問状態数・時間の減り方をプロファイルで確かめる。

## 結果（2026-10-07）

①②③④ を実装し、⑤⑥ は実装して測ったうえで外した。見つかる経路のコストは、4 つの例の図のすべての探索で元のヒューリスティックと一致した（同じ入力で両方を走らせて比べた）。同じコストの経路が複数あるときにどれを選ぶかは変わるので、出力の SVG は変わる。

1 回の探索で訪れる状態数（平均）と、A* にかかった時間（1 回あたり、全スレッドの合計を探索回数で割ったもの）:

| 入力 | 元 | ①②③ | ①②③＋④ | ①②③＋④＋⑤⑥ |
|---|---|---|---|---|
| 注文 DFD（arrange） | 4161 / 1.54 ms | 2135 / 1.23 ms | 1191 / 0.98 ms | 829 / 1.80 ms |
| ストアフロント（arrange） | 9202 / 2.64 ms | 5149 / 2.25 ms | 3206 / 1.69 ms | 2207 / 2.71 ms |
| C4（arrange） | 4520 / 1.49 ms | 2081 / 1.13 ms | 1196 / 0.87 ms | 833 / 1.60 ms |
| 融資審査 DFD（arrange） | 20456 / 6.98 ms | 10949 / 5.35 ms | 8422 / 4.79 ms | 6464 / 7.52 ms |
| 合成 25 箱・60 本（fix） | 42298 / 7.72 ms | 35291 / 7.39 ms | 29178 / 6.79 ms | 24332 / 9.41 ms |

- ①②③ で訪問状態数はほぼ半分になった。
- ④ はさらに 2〜4 割減らし、計算も行・列ごとの累積和で O(1) なので、時間も減った。
- ⑤⑥ は訪問状態数をさらに減らすが、仕切り線の下限を求める計算（遅延計算にしても、探索が届く列・行ごとに O(行数)）が減った分より重く、時間はかえって増えた。終点の候補が 12 個ある辺の選択の探索で特に重い。
- 推定値をキャッシュする配列（1 回の探索で数 MB）を確保すると、それだけで遅くなった。待ち行列の要素に到達時のコストを持たせて、取り出したときの再計算をなくした。

arrange 全体の時間は、選ぶ経路が変わると arrange の進み方も変わるので、比べにくい。融資審査 DFD では探索回数が 35574 → 40677 回に増え、全体では 41.5 秒 → 45.8 秒と遅くなった。ほかの 3 つは 4.2 → 3.7 秒、6.4 → 3.8 秒、12.0 → 7.2 秒と速くなった。

⑤⑥ をもう一度試すなら、仕切り線ごとの距離変換をやめ、「壁の区間」（通れない・交差する行の連続）の一覧から各位置の下限を二分探索で求めるなど、探索が届く範囲だけを安く計算する方法が要る。
