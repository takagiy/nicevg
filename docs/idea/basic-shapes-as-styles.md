# 基本図形も style で描く

## きっかけ

ライブラリの API に一貫性を持たせたい。今は矩形と円だけが組み込みの図形（`shape`・`width`・`height`・`label`）で、それ以外は `class` と `style` で描く（[style](custom-node-style.md)）。基本図形も同じ `style` で描けるようにする。

```ts
import { render } from "nicevg";
import { box, circle } from "nicevg/style/simple";

const image = render({
  nodes: [...],
  edges: [...],
  style: { box, circle },
});
```

## 今の差

style 付きノード（`data-custom`）は「動かすだけの絵」で、組み込みの図形が受けている次の扱いを受けない。基本図形を style にするには、これを style の側から伝えられるようにする。

| 扱い | 組み込みの図形 | style 付きノード |
|---|---|---|
| 円の形 | 線は円周で止まり、横切りとラベルの余白も円で判定する | いつも外接矩形として扱う |
| ラベルが収まるかの検査 | 内側の余白 12px に収まるかを調べる（`text-overflow`） | 中の文字をラベルとして扱わない |
| 収まるように広げる | 修正が箱や円の半径を広げる | 大きさを変えない |
| 包含ノードのタイトル | 配置調整で子を動かすとき、ほかのノードのラベルを避ける | ラベルの範囲がないので、子がタイトルに重なりうる |
| 揃い | 円は中心だけで揃える | 矩形として扱う |
| 結果（`report`） | `shape: "circle"` と `labelBounds` を持つ | どちらも持たない |
| 複数行のラベル | `\n` で行を分けられる | `text()` は 1 行だけ |

## 案

### 範囲と形を示す: `data-bounds`

style の絵の中で `data-bounds` を付けた `<rect>` か `<circle>` を、そのノードの範囲と形にする。`<circle>` なら円形のノードとして扱う。付けた要素がなければ、今どおり描いたものの外接矩形を範囲にする。これで表の「円の形」「揃い」「`report.shape`」がそろう。

```svg
<g data-node="user" data-custom="true">
  <g transform="translate(40 200)">
    <circle data-bounds="true" cx="40" cy="40" r="40" fill="white" stroke="black"/>
    <text x="40" y="40" font-size="14" text-anchor="middle" dominant-baseline="central">User</text>
  </g>
</g>
```

- `data-bounds` の要素の外にある図形（影、飾りの線）は範囲に入らない。
- SVG は XML なので、値のない属性は書けない。`data-bounds="true"` と書く。
- 結果の `bounds` は今と同じく外接矩形で、円なら `shape: "circle"` が付く。

透明な範囲は、塗りも線もない `data-bounds` の矩形で書く。nicevg は形だけを読み、塗りや線の有無は見ない。絵より広く場所を取りたいとき（アイコンと名前を 1 つのノードにする、など）に使う。`fill` を省くと既定の黒で塗られるので、`fill="none"` を書く。

```svg
<rect data-bounds="true" width="100" height="80" fill="none" stroke="none"/>
```

採らなかった名前と示し方:

- `data-outline`: CSS の `outline` プロパティとまぎれる。
- `data-node-shape`: `data-node` の仲間と分かるが長い。
- `data-shape`: `data-shape="circle"` のように形の名前を書く属性に見える。
- `data-frame`・`data-boundary`: 包含ノードの枠や境界とまぎれる。
- グループに形の名前を書く（`data-shape="circle"`）: どの円が外形か分からず、範囲を描いたもの全体から取ると影や飾りが入る。
- 絵の最初の `rect`・`circle` を外形とする（今の規則のまま）: 属性が要らないが、外形が並び順で決まり、影を先に書くと影が外形になる。
- style が外形を JavaScript の値で返す: style が SVG を返す関数でなくなり、手で書く SVG では使えない。
- id で指す: 同じ style のノードが複数あると、ノードごとに id を作る必要がある。
- 形から推定する: 影や飾りがはみ出すと外れ、意図と違う結果を黙って出す。

### 角の丸み

`data-bounds` の `<rect>` の `rx`・`ry` は、横切り・障害物・ラベルの余白では無視する（角を尖ったものとして扱い、安全な側にずれるだけ）。

端点だけは扱う。今は端点を辺の全長に等分して並べるので、端点が角から `rx` 以内に来ると、線が尖った角の位置で止まり、丸い枠との間に隙間ができる（`rx="8"` で角から 2px なら約 2.7px）。端点を並べる範囲（`spread_side`）と、向かい合う辺を直線に揃える範囲から、角の丸みの分を除く。組み込みの箱にも同じように効く。pill のようにまっすぐな部分がない辺では範囲が 1 点になるので、複数本のときの決めごとが要る。

### 大きさは TypeScript 側で決める

style がラベルから自分の大きさを決め（`box` なら `max(width, ラベルの幅 + 24)` など）、nicevg は style 付きノードを動かすだけで、大きさを変えない。修正の途中で style を呼び直して広げる案は、1 回の呼び出しで描く今の作りが崩れるので採らない。

### 絵の中の文字

style 付きノードの絵の中の文字は、印を付けなくても、全部そのノードのラベルの範囲（`labelBounds`）として読む。テキストにほかのノードが重なってもよい場面はまれなので、避けるのを基本の動きにする。

- 配置調整は、ほかのノードのラベルに 4px 以内まで近づける移動を採らない（`arrange.rs` の `LABEL_CLEARANCE`）。これで、包含ノードの絵の中のタイトルに子が重ならなくなる。
- 結果の `report.labelBounds` にも入る。
- ラベルが内側の余白 12px に収まるかの検査（`text-overflow`）は、style 付きノードには行わない。大きさは style が決め、nicevg は変えないので、検査しても直す手段がない。全部の文字に当てると、絵の端に置いた文字（データストアの ID など）を誤って報告する。

ラベルを示す印（`data-node-label` など）は要らない。

`data-bounds` より外に置いた文字（アイコンの下の名前など）は、範囲の外にある。ほかのコネクタは自由ラベルから 8px 離れて通るが、ノードの文字はその対象ではないので、その文字の上を通りうる。はみ出した文字もコネクタに避けさせるなら、経路探索の障害物に加える。

### DSL とパッケージ

- `text()` が `\n` を受け付け、`<tspan>` の行として書き、`width`・`height` も複数行で測る。
- `package.json` の `exports` に `./style/simple` を足し、`src/style/simple.ts` に `box` と `circle` を置く。
- `box`・`circle` は組み込みの見た目を再現する（白い塗り、黒い線、ラベルは 14px で中央、包含ノードのタイトルは左上から 12px 内側）。出力がバイト単位で同じである必要はない。

## 決めていないこと

- `data-bounds` の外にはみ出した文字を、コネクタの経路の障害物にするか。
- `class` のないノードの扱い: 組み込みの描き方を既定として残すか、`class` を必須にするか。必須にすると一貫するが、`class` なしで箱を渡している今のコード（README の例やテスト）を壊す。Rust の `Sketch`（rect・circle）はライブラリの内部の形として残してよい。
- pill のように、まっすぐな部分のない辺に複数の端点が来るときの並べ方。

## 進め方の案

1. 角の丸みの端点（組み込みの箱にも効く）。
2. `data-bounds` を SVG の約束に足し、style 付きノードの絵の中の文字をラベルの範囲として読む。
3. 複数行の `text()` と `nicevg/style/simple`。
4. `class` のないノードの扱いを決めて移行する。

## 結果（2026-10-16、box と circle）

- Rust: style 付きノードの絵の中の `data-bounds="true"` の `<rect>`・`<circle>` を範囲と形にし、絵の中の文字をすべてラベルの範囲として読む。style 付きノードには `text-overflow` の検査をしない（`DiagramNode.custom`）。
- TypeScript: `nicevg/style/simple` に `box` と `circle` を置いた。組み込みのノードと同じマークアップ（白い塗り、黒い線、`<tspan>` の行）で描き、ラベルが収まらなければ、修正の `expand_nodes` と同じ式（文字の幅は四捨五入、余白 12px、円は `radius_enclosing` の切り上げ）で自分で広がる。
- 親子のない例の図（融資審査 DFD、注文 DFD、README の例）を Sketch に直し、`class` なしと `box`・`circle` で描いて、配置調整の結果（ノードの範囲と形、ラベルの範囲、経路、エッジのラベル、残る問題）が小数 6 桁まで同じになった。`box` の広がり方を変えると 3 つのうち 2 つで違いが出た。
- 本体の速さは変わらない: 4 つの例の SVG の配置調整で、変更前とライブラリを交互に入れ替えて 25 回ずつ測り、中央値の差は −0.9%〜+0.7%。出力はバイト単位で同じ。
- 親子のある図（包含ノードのタイトルを左上に置く描き方）は、まだ `box` で描けない。
