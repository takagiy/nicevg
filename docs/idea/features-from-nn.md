# 小さな NN の中間層から、ふるい分けの特徴を選び直す

## きっかけ

ふるい分けのモデル（XGBoost の yes/no）は、34 個の特徴を使っている。この 34 個は、以前の物差し（上位 16 件に本来の手が入る割合）で特徴を選んだ結果だ（docs/adr/screening-features.md）。S と品質の両方で比べるようになってから（docs/adr/judge-speed-per-call.md）、選び直してはいない。

小さな NN を記録で学ばせると、入力を 34 個から、記録の数値の列 120 個（答えに当たる列と時間の実測値を除いたもの）に広げたときに良くなった（fold 2、S 25% で分かれる図の割合、nicevg-lab の `learn/nn_screen.py`）:

| NN | 34 個の特徴 | 120 列 |
|---|---|---|
| 候補ごとに、上位 3 件か | 34.7% | 29.6% |
| 候補ごとに、上位 5% か | — | 28.0% |
| ステップ全体を見て、softmax | 31.9% | 27.6% |

（XGBoost の yes/no は、34 個の特徴で 25.6%）

34 個の外の列にも、NN が使える情報がある。中間層（出力の手前の 32 個の単位）の各単位が、どの入力と一緒に動くかを順位相関で調べ、影響の大きい単位がよく追っていた列を、特徴の候補として選び出す。

## 中間層から分かったこと

影響の大きい単位は、次の 4 つのまとまりに分かれた（上位 3 件を学んだ NN）。

| まとまり | 一緒に動く入力 |
|---|---|
| 動かすノードの線の混み具合 | 試しの引き直しの前と後の交差、ほかの線との干渉（`trial_crossings_before`、`trial_against_before`、`trial_against_after`、順位相関 0.69） |
| 試しの引き直しでの改善 | `trial_total_change`、`trial_cost_change`（0.50） |
| 図全体の散らかり具合 | `diagram_crossings` 0.78、`diagram_bends` 0.77、`score` 0.76 |
| ステップの大きさ | `candidates`、`diagram_connectors`、`nodes_with_moves`（0.4〜0.5） |

正解を上位 5% にすると、ステップの大きさを追う単位が上位から消え、代わりに候補を見分ける単位が増えた。

- 小さくずらす手の向き: `kind_nudge` 0.76、`nudge_off_rank` 0.74、`nudge_l_crossings_rank` 0.67
- ノードの前のステップの結果: `node_prior_best`、`node_prior_mean`
- ノードの線の絡まり: `attached_bends`、`attached_crossings`

正解の割合がステップの大きさで変わる上位 3 件では、ステップの大きさを学ぶのに力を割く（docs/idea/screening-attempts.md の「yes/no を候補ごとに学ぶことの弱点」）。上位 5% ではその必要がないので、候補を見分ける単位に力が回る。

XGBoost が見逃す手で値が違う単位は、図全体の散らかり具合、ステップの大きさ、線の混み具合だった（z = +1.0〜+1.25）。どれも「散らかった大きいステップの、線の混んだノード」という状況を表す単位で、そのステップの中でどの手かを見分ける単位ではない。見逃す手を見分けるのに要る「ほかの線の問題がどう解けるか」を表す単位は、見つからなかった。

## 特徴の候補

34 個に入っていない列のうち、影響の大きい単位がよく追っていたもの:

| 候補 | 列 | 34 個との違い |
|---|---|---|
| 試しの引き直しの前と後の値 | `trial_crossings_before`、`trial_against_before`、`trial_against_after`、`trial_bends_before`、`trial_bends_after`、`trial_searches` | 34 個には変化量（`trial_total_change` など）だけが入っている。前の値は「今どれだけ混んでいるか」、後の値は「動かした先でどれだけ混むか」を別々に表す |
| 図全体の散らかり具合 | `diagram_bends`、`diagram_crossings`、`score` | 34 個には、線 1 本あたりの値（`bends_per_connector`、`crossings_per_connector`）だけが入っている |
| 動かすノードの線の交差 | `attached_crossings` | 34 個には、曲がりの数（`attached_bends`）だけが入っている |
| 小さくずらす手の向き | `kind_nudge`、`nudge_off_rank`、`nudge_l_crossings_rank` | 向きの見分けが苦手なことは前から分かっていた（docs/idea/screening-weak-spots.md） |
| 前のステップの結果（欠けた値を 0 で埋めた版） | `node_prior_best`、`node_prior_mean` | 34 個には欠けた値のままの版（`~` の付いた列）が入っている |
| 移動の届く範囲にある問題の数 | `issues_near`、`label_issues_near`、`near_miss_near` | 記録を再生して足したもの。XGBoost に足すと、分かれる図の割合が 25.6% / 25.4% → 25.0% / 24.8%（fold 2 / fold 4） |

## 確かめ方

XGBoost に次の 2 通りを足して、S 25% で分かれる図の割合を比べる（fold 2 と 4、学習用の図の 25%、nicevg-lab の `learn/exp.py`）。

1. 120 列すべて
2. 上の表の列だけ

あわせて、XGBoost の正解を上位 5% にした場合も比べる。NN で、ステップの大きさに割く力が減ったからだ。

## 結果

S 25% で分かれる図の割合（fold 2 / fold 4、学習用の図の 25% で学んだもの）。「最も悪い由来」は、図の由来ごとの割合のうち最も高いもの。

| XGBoost の入力と正解 | 分かれる図の割合 | 今の方式との差 | 最も悪い由来 |
|---|---|---|---|
| 34 個の特徴、上位 3 件か（今の方式） | 25.6% / 25.4% | — | 38.4% / 51.1% |
| 34 個に、上の表の列を足す | 24.0% / 24.0% | −1.7 / −1.4 | 38.2% / 43.1% |
| 120 列すべて | 23.4% / 21.5% | −2.2 / −3.9 | 37.8% / 36.8% |
| 34 個の特徴、上位 5% か | 24.8% / 22.8% | −0.8 / −2.6 | 38.1% / 43.6% |
| 34 個に上の表の列を足し、上位 5% か | 22.5% / 22.1% | −3.2 / −3.3 | 37.6% / 49.6% |
| 120 列すべて、上位 5% か | 21.8% / 21.9% | −3.8 / −3.5 | 35.4% / 46.4% |
| 120 列すべて、上位 1% か | 23.8% / 22.3% | −1.8 / −3.1 | 36.4% / 37.4% |
| 120 列すべて、上位 2% か | 21.5% / 20.8% | −4.1 / −4.6 | 32.6% / 41.9% |
| 120 列すべて、上位 3% か | 21.9% / 20.5% | −3.7 / −5.0 | 34.5% / 40.0% |

NN で見つけた列も、正解を上位 5% にすることも、XGBoost で効いた。どちらも、これまで試した方法（docs/idea/screening-attempts.md）のどれより大きい改善だ。120 列すべてを使うと fold 4 で最も良く、最も悪い由来の割合も下がった。表の列だけでは拾えない情報が、残りの列にもある。

120 列すべてでは、正解を上位 2〜3% にしたものが両方の fold で最も良い。木の設定（木の数、深さ、木ごとに使う列の割合）を変えても、差は ±0.5 ポイントの中に収まった。学習用の図を増やすと良くなり、上位 2% で 25% → 50% → 100% と増やすと 21.5% → 19.9% → 19.3%（fold 2）、20.8% → 20.2% → 18.8%（fold 4）だった。34 個の特徴では、学習用の図を 25% にしても結果は変わらなかった。列が増えた分、データが足りなくなっている。上位 1% では、正解がほぼ各ステップの最良の 1 手だけになり、悪くなる。それでも、品質の条件を満たすのに要る 15% 前後には届かない。最も悪い由来の割合は、fold 4 では 120 列だけ（上位 3 件）の 36.8% より高い。

## 気をつけること

- 根拠は相関だけだ。中間層の単位がある列と一緒に動くことは、その列が並べ替えに効くことを意味しない。
- NN に効いたからといって、XGBoost にも効くとは限らない。XGBoost は木の分割で、生の値から差や比を自分で作れる。NN は、前と後の値の両方を渡されて初めて差を作れる。NN が 120 列で良くなったのは、それだけかもしれない。
- 中間層は、点数差を直線で当てる力がむしろ低かった（R² 0.21〜0.23、入力そのものからは 0.28）。分類で学ぶと、点数差の大きさの情報は中間層で失われる。
- 見逃す手を見分けるのに要る情報は、表の特徴の外にある見込みが高い。図の位置関係をそのまま読むグラフ NN（`learn/gnn_screen.py`、nicevg の `examples/snapshot.rs` で書き出したステップごとの図を使う）で確かめている。作りを先行研究に合わせて変える案は docs/idea/read-drawing-with-nn.md にある。
